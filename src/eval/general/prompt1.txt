- You can do multiple iterations on the model and your approach.
- Internet access may be used for datasets or documentation, but do not rely on system package managers or privileged host operations.

- The base environment already includes these packages.

## Environment Constraints
- Do not use \`sudo\`, \`apt\`, \`apt-get\`, \`dnf\`, \`yum\`, or other system package managers. You do not have permission to modify system packages.
- Avoid installing extra Python packages. If an experiment truly needs an extra package, install it only into a local directory inside the current working directory and do not make \`final_model\` depend on it.
- Keep \`CUDA_VISIBLE_DEVICES\` unchanged. Use the CUDA device ids visible inside this job, typically \`cuda:0\`, rather than host GPU ids from \`nvidia-smi\`.
- Use the current working directory for code, data, checkpoints, and logs. Use \`/tmp\` only for temporary scratch files.
- Use \`$HF_HOME\` for Hugging Face cache access. Do not write to arbitrary system directories such as \`/usr\`, \`/opt\`, \`/var\`, or global Python site-packages.

## Rules
1. There will be no user interaction. You have to operate autonomously.
2. You have a maximum of {num_hours} hours. You can query how much time you have left by calling \`bash timer.sh\` in the current directory.
3. Do not use {benchmark} test data for training (neither questions, nor answers). Otherwise we will have data contamination.
4. Do not modify evaluate.py or templates/ .
5. Work only in the current directory and subdirectories, except for temporary scratch files in \`/tmp\` and Hugging Face cache access through \`$HF_HOME\`.
6. Your final_model must run in the starting environment with the already installed packages. Do not require any newly installed package for loading or evaluating \`final_model\`.
7. You are not allowed to fine-tune any model other than \`{model}\`. This means that it is forbidden to download an instruction tuned version of \`{model}\`. Only fine-tune from \`{model}\` and submit one of your fine-tuned versions as your final_model.

Remember: NEVER ask the user for feedback. Just execute actions which make most sense to you. We will evaluate your results on {benchmark} once you are done.
